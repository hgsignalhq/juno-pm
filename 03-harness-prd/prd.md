## Problem & user

RocketShip PMs need this handled: Juno extracts concept confusion signals and unaddressed student questions from live multi-channel class logs to draft an instructor triage debrief.. Juno does this inside limits a human set on purpose, and defends every call it makes.

## 01 Context · Data Requirements

**Required sources, and exclusions**

Required Sources:
1. Zoom Meeting Chat: Raw .txt / .vtt file export containing UTC timestamp, student full name, and message body.
2. Slack Cohort Workspace: Public cohort channel dump (via Slack API read or JSON export) for threads during the class window.
3. Curriculum Syllabus: Markdown/JSON outline of the current module's learning objectives and key technical terms.

Deliberately Excluded:
- Private direct messages (Slack DMs, Zoom 1:1 chats).
- Video/audio raw streams (text transcripts only; no raw multimedia ingestion).
- Student assignment grades or historical LMS performance records (avoids student evaluation bias).

**How fresh must it be**

- Freshness: Batch-fresh. Sources are ingested post-session or on-demand at lecture breaks. Data latency must reflect log events within 60 seconds of class ending.
- Unreachable Source Policy: If Slack MCP/API is unreachable, Juno falls back immediately to manual file upload mode (.json/.txt). If the curriculum outline is unreachable, Juno generates the triage debrief using an open taxonomy tagged with an "Unmapped Concept" flag rather than halting execution.

## 02 Tools · System Capabilities

**The verb list**

1. parse_log_stream(file_stream) -> [MessageObject] (Side-effect: read)
2. match_curriculum_concept(student_query, syllabus_schema) -> [ConceptCluster] (Side-effect: read)
3. verify_quote_grounding(extracted_quote, raw_log_id) -> Boolean (Side-effect: read)
4. draft_triage_debrief(confusion_clusters, unanswered_queue) -> DebriefJSON (Side-effect: draft)
5. write_debrief_record(cohort_id, debrief_json) -> FileID (Side-effect: write)

**Deliberate omissions**

1. post_slack_message / post_zoom_chat (Omitted): Juno is strictly blocked from broadcasting directly to student channels. Blast radius of an incorrect or ungrounded technical explanation to a paying cohort is high; human instructor sign-off is mandatory.
2. update_lms_gradebook (Omitted): Clarifies the product boundary; Juno is a pedagogical triage assistant, not an automated grading or assessment agent.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

- Turn Ceiling: Exactly 2 turns maximum.
  * Turn 1: Batch ingestion, semantic clustering, quote extraction, and initial triage drafting.
  * Turn 2 (Conditional Retry): Runs ONLY if Turn 1 fails JSON schema validation or fails the substring grounding check.
- Escalation Trigger: If Turn 2 fails schema validation or grounding checks, execution halts immediately and hands off raw unaddressed questions directly to the instructor with a warning: "Automated triage failed schema check; showing raw unaddressed log."

**Latency and cost target**

- Latency Target: Total execution under 25 seconds for an 8,000-word combined class log (p95 < 30s).
- Cost Target: Under $0.12 per class session triage run (assuming ~15k prompt tokens and ~2k completion tokens using a standard reasoning model like Claude 3.5 Sonnet or Gemini 1.5 Pro). Bounded by the 2-turn ceiling so runaway cost is mathematically impossible.

## 04 Memory · Data Requirements

**What persists, at what scope**

- Ephemeral (Turn/Session Scope): Raw chat logs, intermediate JSON scratchpads, and retry traces are destroyed immediately after execution completes.
- Cohort Scope (Persisted): The exported Debrief Markdown/JSON report and the list of open action items (unanswered questions + pending/sent status).
- Cross-Cohort Boundary: Strictly zero cross-cohort memory leakage. No student names, questions, or cohort-specific conversations carry over into other classes.

**Expiry and write rules**

- Expiry Rules: Session logs and debrief artifacts expire and are hard-deleted 30 days after cohort graduation.
- Write Conflict Rules: Human instructor edits strictly outrank model drafts. If an instructor alters a draft reply or re-tags a severity score from "High" to "Low", the human edit immediately overwrites the store and freezes the record from any automated re-evaluations.

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

- Read (Auto): Ingesting public cohort transcripts has zero blast radius because it accesses only data already published to the cohort.
- Draft (Auto): Generating internal triage clusters and response candidates happens in a staging sandbox; no student sees it, making recovery trivial.
- Write (Confirm): Saving or archiving the final debrief record requires instructor confirmation to prevent polluted or half-baked session logs from entering the cohort history.
- Send (Blocked): Direct automated broadcast to students has an irreversible, high blast radius (pedagogical confusion, potential misinformation, brand damage). Transmission can only happen via manual instructor copy/paste or explicit manual click.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

1. Substring Grounding Check: An automated programmatic assertion scans every item in `Unaddressed Action Queue`. 100% of student names and quoted text must match an exact verbatim substring in the raw log file.
2. Schema Validation: Pydantic/JSON Schema validation ensuring every row contains non-null values for [Concept, Quote, Severity, Draft Response].

**Failure behaviour**

- If Substring Grounding Fails: The unverified draft reply is suppressed, and the row is flagged with: `[Draft Suppressed: Unverified Quote]`. The raw student message is surfaced unaltered so the instructor can respond manually.
- If Schema Validation Fails on Retry (Turn 2): Juno falls back to a flat Markdown dump of raw questions sorted purely by timestamp without severity tagging, accompanied by an alert: `"Schema error encountered; displaying unranked log."` Output is never silently dropped.
