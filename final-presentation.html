Module 1
Skill file
Role

You are Juno Signal Triage, an expert AI Teaching Assistant and Classroom PM Agent. You analyze multi-channel student communications (Slack cohort threads, Zoom live chat logs, and Zoom post-meeting transcriptions) to identify pedagogical friction and operational gaps. You never provide generic praise, hallucinate student sentiment, or make broad summaries without direct evidence.

Task

Ingest unstructured communication logs from a live class session and generate a structured cohort debrief:
1. Synthesize concepts that did not land well, grouping by confusion frequency and citing verbatim student questions.
2. Flag all unaddressed student questions, identifying the student's name, platform origin, the exact question, and a draft response ready for the instructor to review and send.

Module 3
AI PRD
Problem and user

RocketShip PMs need this handled: Juno extracts concept confusion signals and unaddressed student questions from live multi-channel class logs to draft an instructor triage debrief.. Juno does this inside limits a human set on purpose, and defends every call it makes.

Permissions

The permission tier

| Side-effect class | Tier |
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

Justification

- Read (Auto): Ingesting public cohort transcripts has zero blast radius because it accesses only data already published to the cohort.
- Draft (Auto): Generating internal triage clusters and response candidates happens in a staging sandbox; no student sees it, making recovery trivial.
- Write (Confirm): Saving or archiving the final debrief record requires instructor confirmation to prevent polluted or half-baked session logs from entering the cohort history.
- Send (Blocked): Direct automated broadcast to students has an irreversible, high blast radius (pedagogical confusion, potential misinformation, brand damage). Transmission can only happen via manual instructor copy/paste or explicit manual click.

Module 4
Agent control panel
What it is doing

Juno operates on the Pedagogical Triage pillar: ingesting multi-channel live session logs (Zoom chat and Slack cohort threads) to cluster student concept confusion and draft actionable, grounded instructor replies for unaddressed questions.

Rules of engagement

Agency Permission:

- Autonomous Actions (Decide Alone): Ingest class transcript files, extract timestamps/names, cluster semantically similar queries, tag pedagogical friction severity (High/Med/Low), and draft proposed instructor responses in staging.
- Propose & Wait (Requires Approval): Writing the final debrief report to the cohort archive and queueing draft responses for delivery.
- Blocked Actions (Strictly Prohibited): Sending any message to Slack, posting in Zoom chat, emailing students, or altering student LMS records.

Access Control:

- Read: Public cohort Slack channel history within session timestamp window; Zoom public chat export files (.txt/.vtt); course syllabus outline JSON.
- Write: Juno staging buffer and cohort debrief archive storage (`/cohorts/{cohort_id}/debriefs/`).
- Denied: Direct private messages (Slack DMs, 1:1 Zoom chats), student gradebooks, email servers, external web search APIs, and production Slack/Zoom write webhooks.

Fallback Protocols:

1. On Schema Failure / Tool Error 2x: Abort agentic reasoning loop and output a fallback flat Markdown table containing raw unaddressed questions ordered strictly by timestamp, with an alert banner: "Automated triage degraded; displaying unformatted log."
2. On Source Unavailability (Slack API unreachable): Fall back to prompting instructor for manual .txt / .vtt file drop; do not attempt blind synthesis.
3. On Low Grounding Ratio (<70%): Suppress all synthetic drafts and output only verbatim student messages with timestamps to eliminate hallucinated triage items.

Checkpoints:

1. Pre-Archive Checkpoint: Instructor review screen displaying the generated Concept Friction Table and Unaddressed Action Queue. The debrief document is not committed to the cohort record until the instructor clicks "Approve Debrief."
2. Message Dispatch Checkpoint: Every draft response to an unaddressed student question requires an explicit individual click or edit-and-send by the instructor. Zero auto-dispatch.

Module 6

How I’ll know it’s working

The goal the AI is meant to move, where it stands today, and the result that would make me stop.

The goal

Reduce post-session student question triage and pedagogical debrief time from 30 minutes to under 5 minutes per class session, while resolving 100% of unaddressed live questions within 24 hours.

Baseline

Without Juno, an instructor spends 25–35 minutes manually cross-referencing Zoom chat logs and Slack cohort threads after each lecture, resulting in an average of 3 to 4 unaddressed student questions slipping through per week.

Target and review date

Achieve an average debrief synthesis and review time of <= 5 minutes per session with 0 dropped student questions across 6 consecutive cohorts, reviewed on November 20, 2026.

Usage metric

Instructor debrief adoption rate: >= 90% of completed class sessions run through Juno triage within 2 hours of lecture end, and >= 80% of generated draft responses are approved or sent with minimal edits.

Pattern I’ll watch for first

Instructor edit fatigue: If the instructor regularly rewrites >50% of the draft responses or manually deletes >30% of flagged confusion clusters, indicating semantic drift, poor curriculum grounding, or overly generic draft tone.

Stop line

Any single instance of Juno hallucinating a student quote or student name in a triage debrief, or a drop in instructor response acceptance rate below 50% over two consecutive weeks.

Reflection

What I learned

Where it was hardest, what I’ll keep doing, and the moment my thinking changed.

Friction

Translating high-level agentic ideas into concrete, bounded execution parameters (especially defining the harness, turn ceilings, and tool return schemas). In enterprise PM, we often talk about 'agent intelligence' abstractly; forcing that into rigid stop conditions, deterministic grounding assertions, and cost-per-turn physics was where the real architectural friction surfaced.

Key learnings

1. The harness is the actual product: the model provides raw inference, but the PM defines the loop ceiling, permissions, deterministic verification checks, and escalation boundaries.
2. Structure tool outputs as machine-verifiable objects (status, counts, boolean grounding checks) rather than narrative text so the harness can catch silent failures early.
3. Establish hard deal-breakers in human evals (like verbatim quote matching) before optimizing for subjective quality metrics like style or tone.

Aha moment

Realizing that 'loop size and turn ceilings' are not engineering performance settings, but fundamental cost, safety, and business risk decisions owned by the PM. An agent without an explicit turn ceiling and verification gate isn't an intelligent autonomous system—it's an uncapped financial liability and a hallucination risk.
